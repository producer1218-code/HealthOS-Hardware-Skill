# 定期报告的方法论：从记录到可复盘行动

v0.6 / 2026-10-09。报告采用专业健康观察结构，由确定性计算、公开证据和用户背景共同组成；尚未获得临床专家审核，不能称为医生出具的报告。

## Agent 如何在计算前制定观察方案

先按[个人观察方法](observation-method.md)询问设备和健康问题，将诉求映射到可获取字段、必要背景、权限与复盘周期。已有 Agent 可以在安装前完成提案；[计划模板](../skills/healthos/references/observation-plan-v1.json)不等于运行时配置或实际授权。以下内容描述当前计算与报告原型。

## 推理链

用户确认目标 → 验证访问资格和用途授权 → 读取已授权字段 → 校验日期、单位、来源、算法与缺失 → 分数据流描述本周及上周 → 建立个人基线 → 问背景而不猜病因 → 给出适用的小行动 → 分别记录执行与感受 → 更新可检查记忆。

## 每份报告的七个部分

| 部分 | 回答什么 | 方法和限制 |
| --- | --- | --- |
| 目标与覆盖 | 这份报告为谁的什么目标服务？记录够吗？ | 有效天数、缺失、最新日期和目标状态 |
| 周度描述 | 过去七个完成日期记录怎样？ | 每日按指标聚合，再取周中位数；前七日另列。任一周少于三天标不足，不作可靠变化结论 |
| 个人趋势 | 与同设备/来源/算法的自己相比如何？ | 28 日基线与最近 3 日；至少 14 个基线日、3 个近期日。median/MAD 参数是版本化工程假设 |
| 背景与解释 | 最近作息、佩戴或生活安排改变了吗？ | 显式自述；不能凭 HRV 诊断压力、焦虑或疾病 |
| 下周小行动 | 什么动作可行，依据何在？ | 用公开指南给一般健康行动；数据新鲜、通知授权有效、无拒绝/感觉更差反馈才提出 |
| 复盘和记忆 | 做了吗？适合吗？感受如何？ | 执行与自述结果分开；用户负反馈暂停相应动作，不自动学习临床阈值 |
| 证据与未知 | 哪些有来源，哪些只是本项目设计？ | 链接、支持范围、版本与未审核状态随报告保存 |

周中位数用于描述有记录的日期，不能代表缺失日期。不会计算综合健康评分、疾病概率或用设备估计替代医院参考检查。

## 论文和指南怎样进入代码

| 原始来源 | 支持的原则 | 落地位置 | 不支持的结论 |
| --- | --- | --- | --- |
| [Laborde et al., 2017](https://pmc.ncbi.nlm.nih.gov/articles/PMC5316555/) | HRV 要说明测量条件，考虑活动等情境 | 数据流隔离、RMSSD/SDNN 分开、背景问题 | 低 HRV 等于疾病/压力 |
| [COM-B, Michie et al., 2011](https://pubmed.ncbi.nlm.nih.gov/21513547/) | 行为与能力、机会、动机相关 | 下周动作前询问能力、时间机会与意愿；轮班优先日记 | 本系统的干预已经有效 |
| [CDC 睡眠指南](https://www.cdc.gov/sleep/about/index.html) | 一般睡眠习惯与日记 | 睡眠行动、作息问题 | 本项目阈值或手环睡眠准确性已验证 |
| [WHO 活动指南](https://www.who.int/publications/i/item/9789240014886) | 一般身体活动建议 | 可行的小活动计划 | 步数能证明中高强度活动达标 |

完整研究背景见 [literature.md](literature.md) 与 [evidence-to-code.md](evidence-to-code.md)。当前 COM-B 只是访谈与行动设计框架，不是自动评分工具。无需复制论文全文即可核对源文与本项目解释。

## 可替换 LLM 的职责

reports.py 先算事实并确定有依据的行动，模型只接收允许的聚合包，返回 summary 和 questions。字段、长度、新数字及链接有校验；模型输出仍可能解释错误，因此标为 AI 草稿。数值表、原始证据及本地正文不依赖模型调用成功。自定义报告模型执行可信 Python，不是隔离沙箱。

## 越用越了解的确切含义

memory.json 包含确认目标、用户原文背景、数据覆盖、反馈计数、暂停行动。agent-packet.json 包含这份记忆及当前分析上下文。报告保留每次观察快照，因此你能回看变化；记录变多后可能从校准进入个人趋势监控。没有隐含情绪画像、自动疾病训练或经验证的个体因果学习。

## 报告周期与投递

默认关闭。开启后按用户选择的 1–30 天周期检查，网页提供 7/14/30。第一份在下一轮生成，周期从上一份的分析日计算，观察窗口始终是过去 7 个完成日期。14/30 天只是推送周期，不是 14/30 日数据汇总。相同日的稳定报告 ID 防重。进程需要运行；重启后补一次当前到期报告，不逐份重放停机期间报告。

同日失败/不确定回执不会自动重发，需要核对状态；下一周期可以生成新报告。此版本没有远程自动对账界面。即时行动提醒预算与周期报告分开，避免将“没有异常提醒”误解为“不需要报告”。
