# 第一次看到 HealthOS？从这里开始

你有手环或健康手表，但不知道数字怎么用。HealthOS 提供一条公开、可检查的路径：了解设备能交付什么数据 → 确认自己的目标 → 把允许使用的记录交给自己的 Agent → 按方法论形成定期报告 → 通过反馈更新个人档案。

**阅读本页、设备表、论文映射和完整报告都不需要安装、登录或提供密钥。** GitHub 展示代码和说明；私人健康监控由你部署后运行。

已有 Agent 的用户先把 [START_HERE.md](../START_HERE.md) 交给它，从设备和自己的健康问题开始。Agent 按[观察协议](observation-method.md)说明数据如何被利用，再提出观察方案。合成报告和安装是按需要选择的后续步骤。

## 1. 找到你的设备与数据入口

| 你已有的产品 | 当前 HealthOS 接入方式 | 已实现读取的字段 | 下一步 |
| --- | --- | --- | --- |
| Fitbit / Fitbit Air | 官方 ZIP/目录导出；有资格的 Google 项目可试实验性只读 API | 导出：睡眠、静息心率、明确 RMSSD、步数。API：已处理主睡眠、日静息心率、日均 RMSSD | [Fitbit 指引](google-health-connect.md) |
| Apple Watch / Apple Health | 用户导出的 XML | 心率、静息心率、SDNN、血氧、睡眠腕温；当前不读睡眠时长和步数 | [导入格式](adapters.md) |
| WHOOP 5.0 / MG | 已获授权并保存的 v2 JSON 响应 | 静息心率、RMSSD、血氧、皮温、睡眠时长、呼吸频率 | [导入格式](adapters.md) |
| 华米 / 华为 / 小米 / OPPO / vivo 等 | 当前尚无这些品牌的专用适配器 | 设备宣传指标不能当作本项目可读取字段 | [型号调研与缺口](model-capabilities.md) |
| 其他设备 / 自己的 Agent | 标准 CSV、JSONL 或可替换数据适配器 | 以实际授权、导出和字段映射为准 | [插件协议](plugins.md) |

上述能力来自解析代码与合成测试，不表示每款真实设备都已验证。Google 目前暂停新项目接入；不能用创建 OAuth 客户端代替项目资格。Google API 用户先读[资格与授权说明](google-health-connect.md)，其他用户可以从官方导出开始。

## 2. 明确你希望改善什么

先选择睡眠、恢复、活动等目标，再自愿补充作息、轮班、照护或旅行背景。系统需要知道行动是否符合你的时间、能力和意愿。HRV 不会自动告诉它你的情绪或人格。

逐项选择允许分析的指标，分别确认本地分析、提醒、外部推送和模型分享。你的原始记录和凭证留在自己的私人工作目录；不要通过 Issue、Pull Request 或提交上传。

## 3. 看清楚数据怎样成为报告

允许使用的记录 → 统一日期、单位和来源 → 标注缺失 → 分设备和算法计算 → 对比自己的基线 → 确认生活背景 → 给出有来源的小行动 → 记录执行和感受。

| 方法 | 在系统中怎么用 | 不代表什么 |
| --- | --- | --- |
| HRV 测量研究 | 区分 RMSSD/SDNN、来源与条件，先问背景 | 低 HRV 不能直接诊断压力或疾病 |
| CDC / WHO 公开指南 | 睡眠习惯和可行活动的讨论依据 | 不证明设备准确或项目有效 |
| COM-B 行为框架 | 询问能力、机会、意愿，让行动可执行 | 不是自动心理评分 |
| 个人中位数 / MAD 基线 | 描述同一数据流相对自己的变化 | 参数是工程假设，未经临床验证 |

[逐条核对论文与代码](report-methodology.md) · [查看完整合成报告](sample-health-report.md)

## 4. 接自己的模型与推送渠道

数据接入器、报告模型和投递渠道分别替换。内置模型接口兼容 Chat Completions JSON；其他服务可实现插件。你在部署的私人环境中配置模型、地址与密钥环境变量，不在公开演示里输入密钥。

系统先计算事实和生成本地报告；可选 LLM 接收明确授权的聚合包，补充解释和问题。模型不可改写原始数值或医学规则。报告可按 7/14/30 天交付；观察窗口仍是最近七个完成日期。手机推送需配置并授权自己的飞书机器人。周期运行需要常驻进程。

[部署与配置说明](install.md) · [Agent 交接协议](agent-handoff.md)

## 5. 越用越了解你，具体指什么

系统保存你确认的目标、主动提供的背景、数据覆盖和行动反馈。记录积累后可建立个人基线；拒绝或感觉更差的行动会暂停。记忆可查看和清除，不证明干预有效，也不自动学习临床阈值。

你拿到仓库后可以立刻读懂接入方案、检查方法论、查看成品报告，并把[交接说明](agent-handoff.md)给自己的 Agent。要使用真实数据，再进入[个人部署](install.md)。当前还需要 Python 安装，没有消费者安装包；真实账号接入、外部推送和专家审核仍有验证缺口。
